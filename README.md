# pws-dashboard-template

This is a **scaffold template** — not a live dashboard. It is cloned and configured by [pws-scaffolder](https://github.com/EricPhifer/pws-scaffolder) to generate client-specific dashboard projects.

The Overview and Monthly Reports follow the client dashboard standard (`OVERVIEW-STANDARD.md`, kept in the agency's docs, not in client repos). The Rest of the Story dashboard is the reference implementation this template was ported from.

## Stack

Vite, Vue 3, TypeScript, Tailwind CSS 4, Vue Router, Pinia, Lucide Vue Next, @vueuse/core, @auth0/auth0-vue, chart.js, jose, Resend, Stripe

## Auth

All routes require Auth0 authentication. The router `beforeEach` guard redirects unauthenticated users to Auth0 login.

Every Netlify function calls `requireUser` (`netlify/lib/auth.ts`), which verifies the Auth0 ID token against the tenant's keys. A header that merely exists is not accepted. The browser sends the ID token via `useAuthToken()` + `apiFetch()`. Set `AUTH0_ALLOWED_EMAILS` if sign-ups are open in the tenant.

Functions never take a client, Stripe customer or analytics hostname from the request: those come from `src/config/dashboard.ts` or server-side env (`STRIPE_CUSTOMER_ID`, `ANALYTICS_HOSTNAME`).

## Pages

| Route | Page | Shown |
|---|---|---|
| `/` | Overview: greeting + quick actions, banner, attention strip, month so far, last month's report, latest submissions, from your web team, site health | Always |
| `/reports` | Monthly Reports: one stored snapshot per finished month, printable | Always (every tier) |
| `/submissions` | Form Submissions inbox: search, filters, statuses, notes, attachments, CSV export | `submissionKinds` configured |
| `/analytics` | Analytics: real visitors by day or month (7 days to since tracking began), top pages, sources; Simple Analytics or GA4 | `enabledWidgets` includes `siteAnalytics` |
| `/content-kit` | Content Kit | `contentKit.enabled` |
| `/support` | Contact & Support (emails via Resend) | Always |
| `/billing` | Billing (Stripe + offline invoices from the Pipeline): a paired invoice set (`metadata.pair_id`) shows as one amount due, credit on account and what the next invoice drops to, "Paid offline" for invoices settled outside Stripe; `metadata.hideFromClient = "true"` keeps a bookkeeping-only invoice off the list | `billing.enabled` |
| `/help` | Help & How-To | Always |

The sidebar is generated by the scaffolder from the config. `tutorials` and `contentEditors` in `enabledWidgets` add optional cards under the overview.

**Banners.** `announcements` in `src/config/dashboard.ts` puts a message across the top of the Overview. The first whose `showFrom`/`showUntil` (YYYY-MM-DD, inclusive) includes today is shown, so a banner can be scheduled ahead and swaps on its own; commit and deploy once.

```ts
announcements: [
  { message: 'Your homepage now loads much faster on phones.', level: 'success', // info | success | warning | critical
    link: { label: 'View reports', url: '/reports' }, showFrom: '2026-11-03', showUntil: '2026-11-30' },
],
```

**From your web team.** The latest published monthly note (summary, else recommendations) and the next maintenance day on the agency calendar, through the Pipeline's `client-web-team`. Left out when the Pipeline isn't connected.

**Dark mode** is remembered per browser (`localStorage.theme`); `public/theme.js` applies it before the first paint (a file, so the CSP needs no inline scripts).

## Form Submissions

The website's forms post a copy of each submission to this dashboard's `form-submissions` function with the write-only `FORMS_INTAKE_SECRET` (`X-Forms-Secret` header); the dashboard files it under a kind from `config.submissionKinds` (each with `kind`, `one`, `many`, and a `match` regex on the form's slug/title) and stores it through the Pipeline (`client-form-submissions`). The site never holds the dashboard key. The overview shows new submissions per kind in the attention strip, the five latest beside the month, and counts in "{Month} so far"; each monthly report has a "People getting in touch" section.

## Monthly Reports

- `lighthouse-check` (scheduled daily from the 2nd) tests the homepage with Google PageSpeed and saves it through the Pipeline.
- `monthly-report` (scheduled daily from the 3rd) writes last month's snapshot once.
- Both run only on the **published production deploy**.
- Locally: `pnpm lighthouse:check --write` and `pnpm reports:generate --last 12 --write` (backfill at setup).

Reports, checks, offline invoices and the Content Kit are stored in the agency database **through the Pipeline** (`netlify/lib/pipeline.ts`, `PIPELINE_FUNCTIONS_URL` + `PIPELINE_DASHBOARD_KEY`). The dashboard holds no database credential.

Visit figures come from Simple Analytics, or for GA4 clients from engaged sessions via a service account (`netlify/lib/ga4.ts`, `GA4_PROPERTY_ID`, `GA4_CLIENT_EMAIL`, `GA4_PRIVATE_KEY`); that account can also authenticate PageSpeed in place of `PSI_API_KEY`. GA4 clients' reports also show where visitors were (US towns) and the share coming back. **Google search** (clicks, times shown, average position, top searches; `netlify/lib/search-console.ts`) appears for any provider once the Google service account is added as a user on the site's Search Console property (`GSC_SITE_URL` optional; otherwise found from the domain, preferring a domain property). A Simple Analytics client can set `GA4_CLIENT_EMAIL`/`GA4_PRIVATE_KEY` for Search Console alone.

## Security headers and Sentry

`netlify.toml` sets a strict CSP (scripts from the dashboard only; connections to its functions, the Auth0 tenant and Sentry), HSTS, nosniff and `frame-ancestors 'none'`. The scaffolder narrows `https://*.auth0.com` to the client's tenant. Sentry is optional: set `VITE_SENTRY_DSN` and it loads after the page is idle (`src/monitoring.ts`); replays mask text and inputs.

## Placeholder Pattern

Same `##PLACEHOLDER##` pattern as pws-foundation-template. Theme variables, client name, and VSCode colors are replaced by the scaffolder.

## Setup After Scaffolding

1. Create an Auth0 tenant and SPA application. Set `VITE_AUTH0_*` and the matching server-side `AUTH0_DOMAIN` / `AUTH0_CLIENT_ID`.
2. Issue the client's dashboard key on its Pipeline ClientDetail page. Set `PIPELINE_DASHBOARD_KEY` and `PIPELINE_CLIENT_ID`.
3. Set `PSI_API_KEY`, `SIMPLE_ANALYTICS_API_KEY`, `ANALYTICS_HOSTNAME`, `STRIPE_CONFIG`, `STRIPE_CUSTOMER_ID`, and the Resend vars.
4. Create a Netlify site, connect the repo, add the env vars (secret, Functions scope), and redeploy after any change.
5. After launch: `pnpm lighthouse:check --write`, then `pnpm reports:generate --last 12 --write`.

See `.env.example` for every variable.

## Do Not

- Run this template directly — it requires Auth0 and Pipeline credentials
- Add client-specific widget config here — it goes in the build config from Build Tools
- Put a database credential, Stripe customer ID or analytics key in a `VITE_` variable
- Connect to a database from a function — add a Pipeline endpoint guarded by the dashboard key instead (if one ever must, use `@libsql/client/web`; the prebuild guard rejects the bare import)
